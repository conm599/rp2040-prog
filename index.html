02为什么私有协议要单独处理

这是最容易踩坑的地方：通用的调试器固件，对国产芯片不一定管用。

芯片 / 协议能不能用 debugprobe
STM32 / GD32 / APM32标准 ARM SWD能，直接烧
CH32F103Cortex-M3，SWD 兼容多数能，但建议配 WCH 的 OpenOCD 分支
CH32V003 / V 系列RISC-V + SWIO 单线不能，协议完全不同
WCH CH5xx（蓝牙）USB ISP bootloader不用探针，wchisp 直接走 USB
AVR（ATmega / ATtiny）ISP 或 UPDI不能，需要 FiXPro 这类专用固件
ESP8266 / ESP32自带 USB 或串口下载不需要探针，esptool 就够了

CH32V003 用的是 SWIO 单线协议：把时钟信息编码进数据波形里自同步， 物理上只要一根 PD1。标准 SWD 是数据线加时钟线两根，两者电气层就不同，通用调试器根本没法降级兼容。

WCH 官方的 WCH-LinkE 固件是闭源的，所以社区绕了两条路：一是用 RP2040 或另一颗 CH32V003 重新实现 SWIO 时序（就是上面的 pico_rvd），二是直接走芯片内置的 USB ISP bootloader， 连探针都不需要。

03开源工具链

固件只是硬件那一半，另一半是主机侧的工具。官方工具链不认的芯片，基本都能在这里找到开源替代。

项目适用说明
pyocd/pyOCD ARM Python 写的调试器，命令行友好，支持自定义 target 定义（页大小、Flash 容量都能自己改，兼容片救星）
openocd-org/openocd 通用 最主流的开源调试器，内置 STM32F1 等芯片定义，能自动识别 Flash 容量
openwch/openocd CH32 WCH 官方维护的 OpenOCD 分支，支持 CH32F/V 系列，配 WCH-LinkE 或改过的探针

04刷入步骤

  1. 下载固件
    点上面任意一个下载按钮，得到 .uf2 文件。
  2. 进入 BOOTSEL
    按住板上的 BOOTSEL 键不放，插 USB，然后松手。
  3. 拖进去
    电脑上出现 RPI-RP2 盘，把 uf2 文件复制进去。
  4. 自动重启
    盘符消失、设备重新枚举，固件生效。RP2040 的 bootloader 在 ROM 里，刷错也变不了砖。
FiXPro 刷完直接就能用
刷 FiXPro 之后，点 打开烧录界面 就能连上它。界面走浏览器的 Web Serial，必须 Chrome / Edge / Opera，Firefox 和 Safari 没实现这个 API。
换固件随时可以
想从调试器切回 MicroPython，再走一遍 BOOTSEL 流程就行，没有任何一次性烧录锁。 这也是它比成品烧录器划算的根本原因——功能不是焊死的。
接线提醒
SWD 是直连，GP2 对 SWCLK、GP3 对 SWDIO，不像串口那样要交叉。 另外别把 Pico 的 3V3 和目标板的电源同时接上，两路电源会打架。

05接线说明

以 debugprobe（CMSIS-DAP）接 STM32 / GD32 的 SWD 口为例。四根线，一根都不能凭感觉插。

Pico 引脚目标板说明
GP2SWCLK调试时钟
GP3SWDIO调试数据（双向）
GNDGND必须共地，否则握手失败
3V3(OUT)3V3可选，用 Pico 给板子供电时才接

Pico 上 GP2 和 GP3 是相邻的两个针，GND 就在旁边；目标板上 SWD 口通常是 3V3 / SWDIO / SWCLK / GND 四针，顺序各家不同，认丝印别认位置。

SWD 是直连，不是交叉
串口要 TX 接 RX，SWD 反过来：同名对同名。这是两套东西最容易搞混的地方。 把 SWDIO 接到 SWCLK 上，现象是连不上或者读到全 0。
两个供电二选一
目标板自己插着 USB 或适配器，就把 3V3 那根拔掉，只留三根信号线加地。 两路电源同时接上会互相灌电流，轻则复位异常，重则烧稳压管。
不用管 BOOT0
SWD 直接访问内核，绕过启动模式选择。串口 ISP 那套“拨 BOOT0、断上电卡时序”的流程，这里完全用不上。
不同固件的引脚不一样，别串着用
debugprobe / DapperMime / yapicoprobe 都是 GP2→SWCLK、GP3→SWDIO； pico_rvd 走 CH32 的单线 SWIO，用的是 GP4，还要加 1kΩ 上拉； FiXPro 的 SPI / I2C / UPDI 分散在 GP16–GP21。换了固件，接线就得跟着换。
